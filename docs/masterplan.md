### 1-2. 직접 확인한 사실 (01·05 그룹 스캔)

| 관찰 | 수치 | 시사점 |
|---|---|---|
| **완전 중복 비율 낮음** | 지역화폐: 제목 고유 96.9%, 본문 해시 고유 98.3% | 중복 문제의 본체는 **재배포·유사 기사(near-dup)** → MinHash/임베딩 유사도 기반 처리가 필요 |

### 2-1. 주제 선택 근거 — 왜 지역화폐인가

| 기준 | 지역화폐 (C) | 늘봄학교 (C) | 소상공인 (A) | AI반도체 등 (B) |
|---|---|---|---|---|
| 뉴스 양 | 36,888 (충분) | 16,668 (단신 15%) | 42,453 | 12~15만 (과다) |
| 찬반 대립 | **매우 뚜렷** (여야 예산 공방, 효과 논쟁) | 있음 (교원 업무 부담) | 약함 | 전망 상충 |
| 1차 자료 접근성 | 행안부 보도자료, 법률·개정안, 국회 검토보고서, 예산 분석, 국책연구 보고서 — 모두 공개 | 교육부 보도자료 중심 | 공개 | 특허·리서치 약관 이슈 |
| "언론 vs 원문 서술 차이" 검증 | 효과 논쟁(국책연구 vs 지자체 연구원) + 예산 수치 보도 vs 원문 | 가능 | 약함 | 가능 |
| 시점 질문 소재 | 국비 지원 축소·복원, 2025년 급증 등 연도별 변화 뚜렷 | 2024 전면 시행 | 있음 | 있음 |

→ 가이드가 강조하는 **"양측 근거 제시"와 "출처 신뢰도 구분"을 가장 선명하게 측정**할 수 있는 주제.
**대안:** 늘봄학교 (단신 필터 필수), 소상공인(A, 미니프로젝트 1·2를 상권 도메인으로 했다면 우선 검토).

> 주의: 이후 내용은 D1 = 지역화폐 기준으로 작성. 주제 변경 시 §3·§5의 소스와 질문만 교체하고 나머지 구조·일정은 그대로 사용

## 5. 지식베이스 구축 계획

### 5-1. 제공 뉴스 처리 파이프라인

```
36,888건 ─▶ (a) 관련도 필터 ─▶ (b) 완전중복 제거 ─▶ (c) near-dup 클러스터링 ─▶ (d) 길이·보일러플레이트 ─▶ (e) 샘플링(필요 시)
```

| 단계 | 기준 (Day 1 EDA 기반 잠정값) | 잔존 / 기록 |
|---|---|---|
| (a) 관련도 | R4: 동의어(`지역화폐`·`지역사랑상품권`·`지역상품권`) 제목 포함 **또는** 본문 2회 이상이면서 1000자당 1회 이상 | 19,322 |
| (b) 완전중복 | URL 동일, 정규화 본문 해시 동일 | 18,896 |
| (c) near-dup | 문자 5-gram MinHash Jaccard ≥ **0.7** → 같은 클러스터, 대표 1건(최장 본문) 유지. 구간별 표본 판정 근거는 eda_findings §4 | 16,946 |
| (d) 정제 | <200자 단신 제외, 꼬리말("기사 섹션 분류 안내"·제보·구독 안내)·저작권 문구 절단 | 16,760 |
| (e) 샘플링 | D3 결정에 따름 (전량 또는 연도×매체 층화 샘플링) | 샘플링 전후 분포 비교 |

주의: **관점이 다른 보도는 제거 대상에서 제외** — 반대 의견 기사까지 제거하면 "양측 근거 제시" 평가가 성립하지 않음. near-dup 임계값은 보수적으로.

### 5-2. 직접 수집 대상 (우선순위)

## 6. 평가 설계

### 6-1. 평가셋 (`eval/eval_set.jsonl`) — Day 2 오후 작성, Day 3 오전 gold 확정

| 유형 | 문항 수 | 비중 |
|---|---:|---:|
| fact (단순 사실) | 22 | 37% |
| compare (비교) | 10 | 17% |
| temporal (시점) | 10 | 17% |
| synthesis (종합·판단/상충) | 10 | 17% |
| unanswerable (답변 불가) | 8 | 13% |
| **합계** | **60** | |
| (선택) multiturn | 5 | 질의 재작성 확장 시 |

```jsonl
{"id":"q001","q":"지역사랑상품권 부정유통 시 과태료 근거 조항은?","type":"fact","gold_doc_ids":["law_..."],"gold_clusters":[],"answer_key":"…","source_need":"law"}
{"id":"q055","q":"2030년 지역화폐 발행 규모 전망치는?","type":"unanswerable","gold_doc_ids":[],"answer_key":"근거 없음 → 거절이 정답"}
```

작성 원칙: 질문의 절반 이상을 1차 자료에서 추출(뉴스만으로 답이 되는 질문만 있으면 1차 자료 수집의 효과 측정 불가). 질문 작성 시 정답 문서를 **직접 열어 확인**한 후 answer_key 작성

### 6-2. 지표와 하네스

| 지표 | 산출 | 구현 |
|---|---|---|
| Hit@1/3/5, MRR | 검색 결과를 doc_id(또는 dup_cluster)로 중복 제거 후 정답 순위 | `run_eval.py --retrieval-only` (LLM 호출 없음, 빠름 → 청킹 실험에 사용) |
| 정확도 | 정확 1 / 부분 0.5 / 오답 0 **직접 채점** | `grade_sheet.csv` 생성 → 수기 채점 |
| 출처 정확성 | 인용 [n] 각각이 실제 근거인가 | 채점 시트 칼럼 |
| 거절 정확도 / 오거절률 | unanswerable 중 거절 비율 / answerable 중 거절 비율 | 자동(거절 문구 매칭) + 수기 확인 |
| 응답시간 | 검색·생성 구간별 ms | 자동 |
| 유사도 점수 | top-1 점수를 정답/오답/답변불가별로 저장 | 임계값 설정 근거 그래프 |

결과 저장: `eval/results/{YYYYMMDD-HHMM}_{tag}/` 에 `config.json`, `per_question.jsonl`, `summary.json`.

### 6-3. 실험 계획 (한 번에 변수 하나)

| 태그 | 변경 변수 | 측정 | 시점 |

## 7. RAG 체인 · UI 요점

**체인 (`rag/chain.py`)**: 질문 → (멀티턴이면 대화 맥락으로 standalone 질문 재작성) → 검색(필터: 기간·doc_type) → 임계값 판정 → 컨텍스트 조립(번호·문서종류·발행일 포함) → 생성(스트리밍) → 인용 번호 ↔ 출처 매핑 반환.

**시스템 프롬프트 필수 6항목** (가이드 4-6) + 추가: "답변 상단에 결론 1~2문장, 이후 근거를 출처 종류별(정부원문/연구/언론/블로그)로 구분", "상충 시 '쟁점' 소제목 아래 양측 병렬 제시".

**Streamlit (`app/`)**
- 탭 1 챗: `st.chat_message` + `st.write_stream`, `st.status`로 "검색 중 → 생성 중", `session_state` 멀티턴
- 사이드바 필터: 기간(연도 슬라이더), 문서 종류 멀티셀렉트
- 답변 아래: 번호 출처 목록(제목·발행처·발행일·링크·doc_type 배지), expander로 청크 원문 + `docs.db` 전문 보기, 유사도 점수
- 빈 결과 / 임계값 미달 → 오류 대신 안내문 + 필터 완화 제안
- 탭 2 대시보드 (Plotly): 실험별 Hit@1/3·MRR 막대, 유형별 정확도, 유사도 분포(정답 vs 오답 vs 불가 + 임계값 선), KB 문서종류·연도 분포, 응답시간 분포(E5 전후)
