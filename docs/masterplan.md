### 1-2. 직접 확인한 사실 (01·05 그룹 스캔)

| 관찰 | 수치 | 시사점 |
|---|---|---|
| **완전 중복 비율 낮음** | 지역화폐: 제목 고유 96.9%, 본문 해시 고유 98.3% | 중복 문제의 본체는 **재배포·유사 기사(near-dup)** → MinHash/임베딩 유사도 기반 처리가 필요 |
| 상위 매체가 통신사 | 뉴시스·뉴스1·연합 = 전체의 약 27% (공공정책) | 통신사 기사의 지역지 재배포 가능성 → near-dup 클러스터링 대상 |
| 본문 길이 | 중앙값 800~1,000자, p95 ≈ 2,700자, 최대 5만자 | 대부분 1~3청크. 5만자급 이상치(토크쇼 녹취 등)는 별도 처리 |

| 연도 편중 | 지역화폐 2025년 10,694건(최다), 늘봄 2024년 8,925건 | 특정 이벤트 집중 → 시점형 질문 소재. 2021년은 10/16부터라 과소 |
| 키워드 커버리지 공백 | 가이드의 주제 A 키워드 중 `지역사랑상품권`, `소상공인 정책자금`, `상가 공실률`, `젠트리피케이션` 등은 **제공되지 않음** | 주제 A 선택 시 제공 데이터가 가이드 범위보다 좁은 점을 리포트에 명시 필요 |
| 노이즈 기사 | 지역화폐 키워드가 토크쇼 요약·종합면에 스쳐 지나가는 사례 확인 | **관련도 필터**(제목 포함 또는 본문 등장 ≥2회 등)를 dedup 앞 단계에 배치 |
| 매체명 | 결손 0건 (복구 로직 적용됨) | 매체 분포 분석 바로 가능 |

### 2-1. 주제 선택 근거 — 왜 지역화폐인가

| 기준 | 지역화폐 (C) | 늘봄학교 (C) | 소상공인 (A) | AI반도체 등 (B) |
|---|---|---|---|---|
| 뉴스 양 | 36,888 (충분) | 16,668 (단신 15%) | 42,453 | 12~15만 (과다) |
| 찬반 대립 | **매우 뚜렷** (여야 예산 공방, 효과 논쟁) | 있음 (교원 업무 부담) | 약함 | 전망 상충 |
| 1차 자료 접근성 | 행안부 보도자료, 법률·개정안, 국회 검토보고서, 예산 분석, 국책연구 보고서 — 모두 공개 | 교육부 보도자료 중심 | 공개 | 특허·리서치 약관 이슈 |
| "언론 vs 원문 서술 차이" 검증 | 효과 논쟁(국책연구 vs 지자체 연구원) + 예산 수치 보도 vs 원문 | 가능 | 약함 | 가능 |
| 시점 질문 소재 | 국비 지원 축소·복원, 2025년 급증 등 연도별 변화 뚜렷 | 2024 전면 시행 | 있음 | 있음 |

→ 가이드가 강조하는 **"양측 근거 제시"와 "출처 신뢰도 구분"을 가장 선명하게 측정**할 수 있는 주제.
**대안:** 늘봄학교 (단신 필터 필수), 소상공인(A, 미니프로젝트 1·2를 상권 도메인으로 했다면 우선 검토).

> 주의: 이후 내용은 D1 = 지역화폐 기준으로 작성. 주제 변경 시 §3·§5의 소스와 질문만 교체하고 나머지 구조·일정은 그대로 사용

## 3. 시스템 정의

**사용자:** 기초자치단체 지역경제과 지역화폐 담당 주무관

4. 민원(사용처, 구매 한도, 부정유통) 응대용 근거 확인

| (b) 완전중복 | URL 동일, 정규화 본문 해시 동일 | 18,896 | 18,943 |
| (c) near-dup | 문자 5-gram MinHash Jaccard ≥ **0.7**, 대표 1건(최장 본문) 유지 | 16,946 | 17,566 |
| (d) 정제 | 꼬리말·저작권 문구 절단 후 <200자 단신 제외 | 16,760 | 17,327 |
| (e) 샘플링 | 미적용 (D3: 전량 사용) | - | 17,327 |

- EDA와 실제 적재 차이의 원인: (1) 관련도·길이 판정을 꼬리말 절단 후 본문으로 수행, (2) near-dup을 EDA의 연쇄 병합(union-find) 대신 대표 문서 기준 배정으로 구현하여 A~B, B~C만 유사하고 A~C는 유사하지 않은 연쇄 묶음이 분리됨 → 리포트 4항에 함께 기술

주의: **관점이 다른 보도는 제거 대상에서 제외** — 반대 의견 기사까지 제거하면 "양측 근거 제시" 평가가 성립하지 않음. near-dup 임계값은 보수적으로.

## 7. RAG 체인 · UI 요점

**체인 (`rag/chain.py`)**: 질문 → (멀티턴이면 대화 맥락으로 standalone 질문 재작성) → 검색(필터: 기간·doc_type) → 임계값 판정 → 컨텍스트 조립(번호·문서종류·발행일 포함) → 생성(스트리밍) → 인용 번호 ↔ 출처 매핑 반환.

**시스템 프롬프트 필수 6항목** (가이드 4-6) + 추가: "답변 상단에 결론 1~2문장, 이후 근거를 출처 종류별(정부원문/연구/언론/블로그)로 구분", "상충 시 '쟁점' 소제목 아래 양측 병렬 제시".

**Streamlit (`app/`)**
- 탭 1 챗: `st.chat_message` + `st.write_stream`, `st.status`로 "검색 중 → 생성 중", `session_state` 멀티턴
- 사이드바 필터: 기간(연도 슬라이더), 문서 종류 멀티셀렉트
- 답변 아래: 번호 출처 목록(제목·발행처·발행일·링크·doc_type 배지), expander로 청크 원문 + `docs.db` 전문 보기, 유사도 점수
- 빈 결과 / 임계값 미달 → 오류 대신 안내문 + 필터 완화 제안
- 탭 2 대시보드 (Plotly): 실험별 Hit@1/3·MRR 막대, 유형별 정확도, 유사도 분포(정답 vs 오답 vs 불가 + 임계값 선), KB 문서종류·연도 분포, 응답시간 분포(E5 전후)

- 성공 기준 전 항목 달성 (Hit@3 0.750, 정확+부분 90.4%, 출처 정확성 100%, 거절 정확도 100%, 오거절률 7.7%, 계층 분리 통과)
- 최종 실패 18건(검색) 중 12건은 정답 문서가 문서 단위로 적중했으나 필요한 청크가 컨텍스트에 없음 → 문서 단위 Hit@3가 답변 가능성을 과대평가 (리포트 8-1)
- 비교 문항은 두 대상 중 한쪽만 검색되는 실패가 남음 (q025·q029·q030·q031·q026), 멀티턴 비교 후속 질의에서도 재현 (리포트 8-2)
- v2 전환으로 q038·q049가 거절에서 오답으로 바뀜 (검색된 문서의 주제 불일치를 생성 단계가 걸러내지 못함, 리포트 8-4)
