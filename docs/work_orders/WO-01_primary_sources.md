## 1. 배경

- 프로젝트: 지역화폐(지역사랑상품권) 정책 자료 RAG 질의응답 챗봇. 대상 사용자는 기초자치단체 지역경제과 담당 주무관
- 지식베이스: 제공 뉴스 17,327건 + 직접 수집 자료. 직접 수집한 1차 자료(법령·보도자료·국회 자료·연구보고서)는 약 100건으로, 청크 기준 비중이 2.9%에 불과
- 문제: 검색 평가(Hit@3 0.558)에서 정답 근거가 1차 자료인 문항 대부분이 같은 주제의 뉴스·블로그에 밀려 검색되지 않음
- 과제 요건: 직접 수집한 1차 자료가 지식베이스에서 유의미한 비중을 차지해야 함
- 이 작업의 목적: 질문 영역별로 부족한 1차 자료를 보강하여 커버리지를 넓히는 것. 건수 채우기보다 아래 §2 영역의 공백을 메우는 것이 우선

### 2-3. 선별 기준

- 지역사랑상품권·지역화폐가 문서의 주제이거나 독립된 장·절로 다뤄지는 자료만 포함 (본문에 한두 번 언급되는 자료 제외)
- 예산·결산 분석처럼 일부만 해당하는 장문 자료는 해당 쪽을 `include_pages`로 지정
- 연구보고서는 효과 긍정·부정 결론을 각각 2건 이상 포함하도록 균형 유지
- 발행일을 확인할 수 없는 자료는 제외
- 형식: PDF 우선, 없으면 HWPX. HWP(구형 바이너리)만 제공되는 자료는 다운로드하지 않고 목록에만 기록 (현재 파서 미지원)

## 3. 준수 사항

### 3-1. 수집 공통

- 수집 전 각 사이트의 `robots.txt`와 이용약관을 확인하고 결과를 보고서(§5-3)에 기록
- 요청 간 1.5초 이상 지연, 병렬 요청 금지
- 로그인이 필요한 자료, 개인정보가 포함된 자료 수집 금지
- 공공누리 등 이용 조건 표시가 있으면 보고서에 기록

### 3-2. 자동 수집이 금지된 소스

| 소스 | robots.txt | 처리 |
|---|---|---|
| 의안정보시스템 likms.assembly.go.kr | `Disallow: /` | 다운로드 금지. 자료명·의안번호·발행일·페이지 URL을 수동 다운로드 목록에 기록 |
| 국회입법조사처 nars.go.kr | `Disallow: /` | 위와 같음 |
| 한국지방행정연구원 krila.re.kr | 판정 불명확 | 위와 같음 |
| 블로그·카페 (blog.naver.com, cafe.naver.com) | RAG 목적 봇 접근 금지 | 이번 작업 범위 아님 |

- 수동 다운로드 목록은 프로젝트 담당자가 직접 브라우저로 내려받아 등록

### 3-3. 작업 범위 제한

- 쓰기 허용 경로: `data/raw/reports/W1-*` (파일), `data/manual_sources_wo01.csv`, `docs/work_orders/WO-01_report.md`
- 그 외 파일 수정 금지 (특히 `data/manual_sources.csv`, `data/manifest.jsonl`, `store/`, 코드 전체)
- git 명령 실행 금지
- `.env` 열람 금지, API 키 사용 금지

## 5. 산출물

### 5-1. 원본 파일

- 경로: `data/raw/reports/`
- 파일명: `W1-{순번 2자리}.pdf` 또는 `W1-{순번 2자리}.hwpx` (예: `W1-01.pdf`)
- 웹 페이지(지자체 안내)는 브라우저 PDF 저장 기능으로 본문이 잘리지 않게 저장. 메뉴·광고 영역 포함은 허용

### 5-2. 서지 정보 `data/manual_sources_wo01.csv`

- UTF-8 (BOM 없음), 쉼표 구분, 첫 행은 아래 열 이름 그대로
- 열 구성은 `data/manual_sources.csv`와 동일 (data_spec §3-3), 다운로드한 파일만 기재

| 열 | 필수 | 작성 규칙 |
|---|---|---|
| `file` | O | §5-1 파일명 |
| `source` | O | §4-1 코드 |
| `doc_type` | O | §4-2 코드 |
| `title` | O | 자료 표지의 제목 그대로 |
| `authors` | | 저자, 복수는 `;` 구분 |
| `publisher` | O | 발행 기관 |
| `series` | | 총서·보고서 번호 등 |
| `published_at` | O | `YYYY-MM-DD`, 일자 미상이면 `YYYY-MM` |
| `citation` | O | 참고문헌 형식. 예: `국회예산정책처 (2024). 『2025년도 예산안 위원회별 분석 [행정안전위원회]』. 국회예산정책처.` 웹 페이지는 `기관명 (게시일). 「제목」. URL (접속일 YYYY-MM-DD).` |
| `include_pages` | | 포함할 PDF 쪽 (1부터, 예: `22,112-118`). 문서 전체가 해당하면 빈 값 |
| `downloaded_at` | O | 다운로드 시각, `YYYY-MM-DDTHH:MM:SS+09:00` |
| `note` | | 다운로드 페이지 URL, 효과 긍정·부정 등 자료의 입장, 주의 사항 |

### 5-3. 수집 보고서 `docs/work_orders/WO-01_report.md`

| 절 | 내용 |
|---|---|
| 1. 요약 | 우선순위별 목표량 대비 확보 건수 |
| 2. 다운로드 목록 | 파일명, 제목, 발행일, doc_type, 선정 이유(§2-2 질문 영역) |
| 3. 수동 다운로드 목록 | 자동 수집 금지 소스의 자료: 제목, 발행 기관, 발행일, 의안번호(해당 시), 페이지 URL, 선정 이유 |
| 4. 미확보 내역 | 찾지 못했거나 제외한 자료와 사유 (공개본 없음, HWP만 제공, 접근 제한 등) |
| 5. 소스별 접근성 | 사이트, robots.txt 판정, 이용 조건, 확인 일시 |
| 6. 제안 | 코드 체계 밖의 소스, 추가로 유용해 보이는 자료 |

- 문장은 개조식으로 '~음' 또는 명사로 끝냄, 이모지 사용 금지

## 7. 회신 후 프로젝트 측 처리 (참고)

- 산출물 검토 → `data/manual_sources.csv`에 병합 → `python -m collector manual` → 인덱스 재구축(`docs` → `chunk` → `embed`) → 평가셋 정답 문서 재검증 → 검색 재측정
